# 📋 AI Agent 快捷提示工程 SOP（可直接复制使用）

本文档提供可直接复制、粘贴给任何 AI Agent 的标准提示词模板。无论开始全新项目还是接手现有项目，只需将下方文本复制给 Agent，即可确保 Agent 遵循严密的工程规范。

---

## 🎯 模板一：新项目/项目启动初始化提示词

> 📌 **使用场景**：将 `_Dev` 目录复制到新项目根目录后，在对话的第一句发送此提示词。

```markdown
你好！本项目已引入 `_Dev/` 工程方法论与规范体系。请严格遵守以下开发原则：

1. **研读规范与架构**：
   - 请先阅读 `_Dev/vibe_coding_methodology.md` 中沉淀的核心方法论与工程模式。
   - 保持代码扁平、简洁、高内聚，避免创建多余的冗长深层子目录。

2. **UI 与交互开发铁律**：
   - **零跳动布局**：固定工具栏与核心容器的尺寸，所有模式切换与折叠动效严禁引起同级或父级组件的纵向/横向颠簸。
   - **交互一致性**：核心按键在不同状态（如清屏/全屏/正常）下必须保持物理坐标一致，减少用户认知负担。

3. **版本演进与文档同步（强制守则）**：
   - 每次升级版本，必须自动同步更新：
     1. 工程版本号配置（如 build.gradle / package.json）。
     2. `README.md` 文档（记录新特性、按键布局与发布下载指引）。
     3. Release 说明与 CI/CD 自动构建脚本。
   - 无需开发者每次重复提醒。

4. **复盘沉淀**：
   - 在每轮重大重构或 Bug 修复后，主动将具有通用价值的排错经验抽象整理到 `_Dev/` 目录中。

请确认你已理解上述规范，并输出你对当前项目的分析与执行计划。
```

## 🎯 模板二：功能迭代与重构开发提示词

> 📌 **使用场景**：在进行具体功能开发、重构或修复时使用。

```markdown
请针对当前项目执行以下任务：
[填写你的具体需求，例如：增加自动敲击功能/修改图标/重构布局]

执行要求：
1. **轻量与纯粹**：仅修改必要代码，清理一切无用或过时的临时文件。
2. **布局平稳性校验**：确保动画与状态切换不引起组件位置跳变。
3. **版本与文档对齐**：若涉及版本变动，同步更新版本号、`README.md` 与 Release 说明。
4. **Git 提交自检**：提供清晰规范的 Conventional Commits 提交说明。
```

## 🎯 模板三：单轮开发完成后的复盘沉淀提示词

> 📌 **使用场景**：在完成一轮复杂功能迭代后，让 Agent 总结沉淀通用经验。

```markdown
本轮开发已完成。请对本轮开发过程进行复盘：
1. 本轮遇到的技术难点或踩坑点是什么？
2. 根本原因是什么？解决方案是什么？
3. 将该经验抽象为一条**通用的、跨技术栈可复用的工程方法论**，并追加到 `_Dev/vibe_coding_methodology.md` 中。
```
